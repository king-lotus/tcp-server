## P0 — 与代码不符

### 1. `docs/api-reference.md:318` 把 `rejected` 定义成单一来源

文档：`| rejected | A connection is accepted and closed immediately because max_connections was reached. |`

代码有五处自增，只有第一处是容量：

| 位置 | 触发 |
|---|---|
| `include/tcp-server-mt.h:3236` | `admitted_ >= max_connections`（accept 线程） |
| `:1293` | `epoll_ctl(EPOLL_CTL_ADD)` 失败 |
| `:1309` | `fd_index_` / `conns_` 插入 `bad_alloc` |
| `:1315` | `on_connection_opened()` 返回 false（`conn_shards_` 插入失败） |
| `:1349` | 新连接任务的兜底 `catch`：`rbuf.init` / `wbuf.init` 分配失败 |

后果：运维把 `rejected` 当容量告警读时，`epoll_ctl` 失败或内存不足会被误读成「连接数打满了」。

旁证——同一个仓库的另外两处说法都与代码一致，只有 `api-reference.md:318` 是孤例：

- `docs/architecture-zh.md:421`：`| rejected | 超过 max_connections，或注册失败 |`
- `docs/review/CODE-REVIEW.md:305`：明确记下了「`epoll_ctl ADD` 失败同时计 `epollCtlErrors` 与 `rejected`」是**保留的双计数**，理由是运维要同时看到「总数上升」和「有连接没接成」。

所以这更像是 `api-reference.md:318` 写窄了，而不是代码有错；但改哪边仍应由你定：若 `rejected` 的语义是「被拒绝接入的连接」，改文档一行即可；若要它严格等于容量拒绝，则代码需拆成两个计数器。

**已决**：不拆计数器。`rejected` 保持「被拒绝接入的连接」语义，改的是 `docs/api-reference.md` 那一行；头文件 `server_stats` 补了同口径的注释，并写明它不是单独的容量指标。

## P1 — 公共面缺契约

### 1. `tcp-server-mt.h:910` `wait()` 完全没有注释

实现（`:3011-3014`）：

```cpp
void multi_reactor_server::wait() noexcept {
    while (is_running())
        std::this_thread::sleep_for(std::chrono::milliseconds(200));
}
```

三件读者必须知道、但头文件一个字没说的事：

- 返回条件不是「`stop()` 被调用」，而是 `is_running()` 变假——组件失败同样让它返回（`failed` 一旦置位，`is_running()` 即为假）。
- **在回调里调用它会永久阻塞**：reactor 线程等的是一个只有它自己退出才能满足的条件，而 `stop()` 又要 join 这个线程。
- 200 ms 轮询粒度，小于 `tick_ms` 默认值的一半。

### 2. `tcp-server-mt.h:933` `connection_ids()` 没有注释，而它是唯一会抛异常的公共 API

```cpp
std::vector<uint64_t> multi_reactor_server::connection_ids() const;   // 非 noexcept
```

`out.reserve()` 会分配、会抛 `bad_alloc`。这条路径同时是 `stop_gracefully()`（`noexcept`，`:2997` 每 10 ms 调一次）在内存压力下 terminate 的来源。头文件既没说它会抛，也没说它是 O(连接数) 的快照。

### 3. `tcp-server-mt.h:794` `rbuf_capacity` 有硬下界，但没写

```cpp
size_t rbuf_capacity = MAX_FRAME_SIZE;   // 无注释
```

`start()` 在 `:2762` 要求 `cfg_.rbuf_capacity >= MAX_FRAME_SIZE`（65544），否则静默 `return false`。把默认值写成 65536——一个非常自然的 64 KiB——会被拒绝，而头文件里没有任何一处提示这条下界。同组其它字段（`backlog`、`wbuf_capacity`、`max_pending_bytes`）都写了「start() refuses otherwise」。

## P2 — 存在但不完整

- **`start()` / `stop()` / `request_stop()`（`:894`、`:895`、`:905`）无注释。** 13 条拒绝条件、`stop()` 的 abortive 语义、回调内只置位不 join——这些只写在 `docs/api-reference.md:184-223`，头文件本身没有。头文件是唯一交付物，使用者很可能只看它。
- **`write_budget_bytes`（`:808`）无注释，且字段名与语义相反。** 它实际是 `drain_wbuf_to_socket()` 中**单连接单次 drain** 的上限（防止一个快发者独占 reactor），不是「每轮事件循环的预算」。我上一轮写 API 文档时就在这一条上写错过一次。
- **`max_connections`（`:785`）`idle_timeout_ms`（`:786`）`tick_ms`（`:787`）`num_reactors`（`:784`）`bind_addr`（`:775`）无注释。** 同组 15 个字段里 7 个没有注释、另外 8 个都有，这种不齐会让读者以为剩下这几个「没有需要说明的地方」——而 `tick_ms` 恰好是唯一会触发启动告警的字段（`:2780-2790`）。
- **`stats()`（`:942`）无注释。** 返回内部对象引用（生命周期到析构），且四个流量计数器按轮次批量发布，最多落后一轮。
- **`accepted` / `rejected` / `closed`（`:256-258`）无注释。** 注释从 `frames_recv` 才开始，紧邻的三个字段留白。
- **`offload()`（`:925`）少一句「`true` 不等于会执行」**：`stop()` 会清空池；关闭连接不取消已入队任务。后半句在 `docs/api-reference.md:275` 有，头文件没有。
